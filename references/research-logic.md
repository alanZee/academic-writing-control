# 科学问题牵引：自顶向下设计，自底向上建立结论

用于研究目标、核心主张、大纲及证据安排。此文件是控制论文的通用写作原则；[篇章逻辑](argument-architecture.md)记录 Li–Zhang 样本的一种具体实现。不要把样本的“物理分析→控制设计”路线强制套给所有控制论文，也不为局部语言修改启动整篇规划。

## 1. 分清问题、目标、假说、主张与贡献

| 层次 | 它回答什么 | 写作时怎样使用 |
|---|---|---|
| 科学问题 | 对什么现象、关系、机制、条件或边界还缺乏认识？ | 定义要消除的不确定性；不能仅以“尚无人使用某算法”代替问题 |
| 研究目标 | 本文打算获得哪种新知识，以回答上述问题？ | 用辨别、量化、解释、揭示适用条件等可落实的任务表达；开发工具可以是实现目标的手段，也可构成方法贡献 |
| 候选解释/假说 | 哪些答案可能成立，它们预期产生什么可区分现象？ | 研究开始时保留竞争解释及否定可能，不把偏好的答案定为必须实现的结果 |
| 核心 claim | 完成研究后，证据究竟支持什么明确判断？ | 规划时写候选主张，成文时写经支持的主张，范围、比较对象和条件必须对应证据 |
| 核心贡献 | 相对已有知识，本文增加了什么？ | 新方法、新证据、新机制解释、关系或适用边界都可贡献知识；“新规律”须有相应支撑，不能强行拔高单工况结果 |
| 主旨 | 这些问题、结果和贡献组成怎样一个中心认识？ | 统一全文取舍与阅读路径；不必让每段都直接证明核心主张，定义、可信度和范围段也有必要作用 |

控制任务与科学问题分层表达。例如“抑制涡脱”是控制目标；“在什么条件下稀疏反馈足以支持该任务，学习路径如何影响这一条件”才是可研究的知识问题。学术价值可以来自系统物理、优化行为、信息利用及其相互作用，不要求每篇都发现新的流动物理机制。

## 2. 自顶向下：设计要回答的问题与判别标准

顺序是：**科学问题 → 新知识目标 → 候选主张/竞争解释 → 所需证据与判据 → 实验或推导 → 图表 → 章节/段落任务。** 研究早期的大纲与实验设计可相互迭代；章节不是先钉死的容器。

先用一个紧凑映射组织需要规划的内容；复用已有计划或台账，不默认另建文件：

| 要回答的问题 | 候选答案及替代解释 | 能区分它们的证据 | 条件、指标与判据 | 图表/小节的论证任务 |
|---|---|---|---|---|
| 一个明确的知识缺口 | 可能成立的答案，也写出可能不成立的情形 | 必要比较、干预、推导或已有结果 | 保持哪些因素、改变什么、何种结果支持/不支持哪种解释 | 让读者据此接受哪项局部认识 |

“预期目标”可以是希望达到的性能或想辨别的关系，但**验收标准应检验数据和推理能否回答问题，而非要求结果必定有利**。尽量在看最终结果前确定主要指标、比较条件、评价窗及判别规则；探索结果可提出新问题和新分析，改变标准时说明缘由，不倒置成原先已指定的检验。

优先选能区分解释的最小充分比较，不把每个维度都扩成网格搜索。新的实验需要遵守当时授权、预算和执行环境；写作 skill 中的证据需求不是运行指令。

## 3. 自底向上：从结果建立主张，再完成叙事

顺序是：**可信的实现与实验 → 实际结果/图表 → 观察与比较 → 解释及范围 → 可支持的 claim → 贡献与主旨 → 全文组织与语言。**

- 先理解数据，再写该数据支持的结果段。结果的“定性”既包含现象描述，也包含判断它在论证中属于直接观察、对照支持、机制解释还是未检验推断。
- 候选主张可能被支持、细化或否定。出现不符结果时检查实现、协议及替代解释，再决定是否补证据、修改假说或调整论文结构；不能通过换指标、删掉关键反例让原主张必然成立。
- 撰写可以伴随实验推进：提纲、暂定引言、方法说明和已有结果段可以先写。最终摘要、贡献表述和结论必须来自已获得的认识。不存在必须把全部实验结束后才能写一个字的规则。
- **执行顺序、知识形成顺序和读者阅读顺序可以不同。** 按依赖关系完成工作，按有助于理解的顺序呈现结果。省去无关开发历程不等于隐去影响解释的分析选择或不利证据。
- 自顶向下与自底向上构成循环：底层证据校正上层问题、主张和结构。涉及作者核心主张的实质改变时，按当前授权讨论取舍，不借泛化规则自动替作者改结论。

与程序开发的类比在于分层、接口和可检验标准；区别在于研究需要发现尚不知道的答案。实验的价值在于能判别假说，而不仅是像功能测试一样通过预定期望。

## 4. 从样本迁移到不同控制论文

更通用的主线是：**提出控制中的知识问题 → 用合适的方法或比较获得可判别证据 → 解释差异及其条件 → 形成新认识或设计原则。** 其中设计原则是一种可能产出；不是所有论文都必须以新控制器设计结束。

| 论文重心 | 适合的论证路径 | 方法与知识的关系 |
|---|---|---|
| 物理信息指导控制设计，如源论文 | 物理诊断 → 设计依据 → 控制比较 → 条件化设计认识 | 已有/新得物理信息输入设计，结果检验其价值 |
| 替代模型与计算效率 | 明确计算瓶颈 → 模型可信度 → 目标系统闭环效果 → 成本与适用条件 | 模型替代是方法贡献；预测误差、控制效果与成本的关系可以成为知识问题，不能由提速自动宣布新规律 |
| 新策略优化路径 | 优化路径的差别 → 控制能力与学习行为比较 → 观测/目标等需求的变化 → 条件与可能机制 | 新方法既是贡献，也提供比较不同学习途径的研究工具 |
| 控制机理或动力学认识 | 控制现象 → 可区分解释 → 时空诊断/干预 → 动力学认识 | 不必发明新控制器，贡献可以是解释既有控制为何有效 |
| 信息需求、鲁棒性或适用范围 | 定义所需能力 → 改变信息/条件 → 效果及失效边界 → 适用条件 | 不把范围测试自动叙述成设计创新，也不从个别成功推普遍规律 |

选择路径时先看作者研究目标和已有证据，再看样本怎样承担相同的论证任务。方法替代与策略更新算法不等同：Wang等沿用PPO、主要替换学习环境，不能据此推出优化梯度路径或观测需求的因果结论。性能、迁移和效率等并列主张各有证据线，细分规则见[跨文献对照](cross-source-synthesis.md)。不能因为样本有SFD、DMD、探针优化，就要求新稿逐节复刻。

## 5. 独立教学示例：同一原则的不同用法

以下用三个通用设问展示论证安排，均为教学示例。根据科学问题选择适合的路径；示例中的问题和可能结果不作为新论文的默认主线或实证结论。

| 示例问题 | 对应的知识目标 | 可采用的证据组织 | 需要避免的跳跃 |
|---|---|---|---|
| 执行器位置为何影响振动抑制？ | 辨别位置、模态耦合与控制效果之间的关系 | 共同基准 → 位置比较 → 模态或能量传递分析 → 适用条件 | 由某位置表现最好直接宣布普遍最优 |
| 策略优化路径是否改变观测或目标信息需求？ | 辨别学习途径与有效控制所需条件之间的关系 | 方法与信息前提 → 可比性能 → 信息条件变化 → 解释与范围 | 由新方法成功直接认定需求差异的唯一原因 |
| 测量延迟如何影响闭环性能？ | 确定延迟与响应、稳定性或补偿效果的关系 | 定义延迟及目标 → 延迟变化 → 动力学诊断或补偿比较 → 适用范围 | 将有限工况的经验阈值当成普遍稳定性边界 |

每个示例都允许多个可能答案。实验结果可以支持或改变原先解释，最终主张由证据决定。比较变量、指标、图表和小节数量均随具体研究调整。

## 6. 涉及信息需求或方法归因时的通用检查

仅在相应主张出现时使用，不将其强加给所有控制论文。先定义“需求”是达到什么性能、稳定性或学习成功标准所需的条件，再辨别以下信息：

1. **部署信息：** 传感器、测量变量、位置、历史数据、控制历史或内部记忆。传感器少不自动等于总输入信息少。
2. **建模、辨识或训练信息：** 模型、状态、轨迹、梯度、先验及计算资源。不同方法可能在这些环节获得不同信息。
3. **目标与评价信息：** 计算损失、奖励或测试指标所需的测量、参考状态及诊断量。它们不一定都作为部署输入。

涉及学习控制时，进一步区分训练目标与独立评价指标。只有分清信息所在环节，才能讨论减少了什么需求、付出了什么代价，以及比较是否支持所写解释。

- **可行性：** 某组合达到规定标准，支持它在所测条件下可行；在相同范围内可以检验某条件是否绝对必要。
- **因素依赖：** 要说效果或需求随某因素变化，应有能辨别该因素作用的比较或理论依据，不默认要求完整析因矩阵。
- **机制归因：** 要把差异归于具体机制，需区分其他同时变化因素；一次方法间优劣比较通常不能锁定唯一原因。
- **范围判断：** 有限资源或条件下未成功，界定的是该实现的表现，不能直接推出整个方法族无解或系统物理上不可控。

论文可以明确展示方法价值，同时把新知识写在证据允许的层次。科学目标是获得可判别的认识，成文的主旨应随这些认识形成。
