# 章节与图文论证

按目标章节读取。本文件把[样本画像](source-profile.md)的 O1–O16 转成写作选择，并结合[双文献对照](cross-source-synthesis.md)补充方法与效率论文的论证；顺序和篇幅按现有证据调整，不是固定模板。

需要决定“为何这样分节、这些段如何服务核心主张”时，先按[研究逻辑](research-logic.md)梳理科学问题、目标、证据与判据，再参考[样本篇章逻辑](argument-architecture.md)和[逐段地图](paragraph-map.md)中任务相近的源段；不要仅因小节标题相同就套写。

## 1. Title / Abstract

**标题（O1）：** 优先让读者识别受控系统、控制任务和本文确有证据的研究视角。方法是辨识工作所必需时保留方法名；机制词没有证据就省去。避免同时塞入全部模块、性能形容词与应用承诺。

**摘要（O1、O15）：**

1. 用具体系统与目标进入问题，必要时点出执行器或控制途径。
2. 明确本文要回答的科学问题及知识目标；方法创新稿交代新路径解决何种困难，以及比较能增进什么认识。
3. 只介绍产生核心证据的方法，不做算法教程。
4. 按证据依赖顺序选择主要发现：可以是系统认识指导设计，也可以是方法比较揭示控制行为、信息需求或适用条件；以本文核心问题决定。
5. 收束到条件明确的控制启示。范围限定贴近相应主张，不集中放在最后补救。

实际写成流畅段落，不给每一步机械分句。不要求背景句数、贡献条数或样本同款结果。若只能写性能结果，写清性能和条件，不能为“物理深度”虚构机理。摘要可以有经核验的关键数字，精度与统计含义沿用来源；没有样本数或重复试验时不补造。

研究结果型摘要缺少实证结果时，只给问题与方法已有依据的摘要片段，在正文外说明尚不能形成完整结果摘要；不要为凑字数把材料缺项、验证状态或以后要做的实验写入摘要。用户明确要研究计划/方案摘要时，才使用与该体裁相符的计划语气。

## 2. Introduction / Related work

**目标（O2）：** 把控制任务、已有知识与尚未理解的关系汇合为可回答的科学问题。明确研究要增加什么认识，再说明方法为什么适合回答。

建议依现有文献选用以下推进：

- 系统与物理现象：什么现象需要抑制、维持或操纵，为什么重要，当前讨论的工况是什么。
- 相关动力学认识：哪些已知结果与控制目标相关；只保留后文会用到的理论线索。
- 控制与学习方法：已有工作解决了什么，依赖什么观测、模型、执行器和评价条件。
- 缺口：哪些物理、优化、观测或目标信息与控制表现之间的关系仍待检验，而非把“别人没有使用本算法”当作科学问题。
- 本文定位：研究问题、可用证据与贡献、后文章节依赖。

样本用分小节的双线综述；较短论文可压缩成若干连贯段落。不要强制三段，不按“传统方法/先进方法/我们的方法”价值排序。关键文献可用作者作主语描述其具体发现，背景共识可在句末引用。避免逐篇读书笔记堆叠；一组引文需共同服务于本段论点。

计算或学习方法稿可按“现有控制能力 → 具体瓶颈 → 已有解决途径及剩余问题 → 本文选择”收窄问题；Wang等的引言即以CFD交互成本汇合。不能把算法从未使用、可部署工具或开源代码自动写成科学发现，须说明其实际增加的能力或认识。

新颖性、历史优先权和文献评价需要当前来源核验。样本的“当时尚无研究”不得迁为新稿事实；仅因样本引用某论文，不能将其视作已读文献。

## 3. Problem formulation

**目标（O3、O5）：** 在读者进入控制器之前，把控制问题定义完整。

用对象到约束的顺序组织：几何/系统与坐标 → 标度和参数 → 边界、载荷或外部输入 → 被控量与参考状态 → 可观测量 → 执行器与限制 → 控制目标。图示应帮助定位传感器和执行器，不能靠图注补救正文中缺失的物理定义。

公式先说明用途，再给式子，随后解释符号、单位和适用条件。只写当前方法实际采用的方程；不能把样本中的 jet profile、Reynolds 数、SFD 或边界条件带入另一个系统。控制动作、物理执行器输出与测得响应分别命名。

## 4. Methods / Numerical methodology

**目标（O4、O5）：** 让读者知道每类证据如何得到，以及关键选择为何足够可信。

每个方法模块按需要回答：它解决哪个分析/控制问题 → 使用什么数学或计算对象 → 如何实现关键步骤 → 得到什么可用于后文的量 → 哪项验证支撑使用。不同模块可合并；不要为模仿源论文补出未采用的方法。

- 数值或实验方法：给出影响解释与复现的离散、时间、边界或测量设置；说明验证对象和误差定义。
- 参考状态/动力学诊断：说明状态怎样获得、分析围绕哪个状态、输出量代表什么。
- 控制器：先把 observation、action、reward/objective、物理系统接起来，再交代算法与影响复现的参数。
- 时间设置：分别说明求解步、控制更新间隔、训练 episode、评价窗；不因它们都叫 step 而合并。
- 学习与测试：说明哪些参数训练后固定、哪些测试允许重训或在线更新；读者必须能辨别策略学习与部署控制。

涉及替代模型时，明确数据来自哪里、模型预测什么、策略在哪里学习、最后在哪里评价；这些接口先于模型结构细节。固定执行器形状与策略输出动作分别描述，不将状态预测器写成新控制器。

全局接口先定义，局部选择在其科学动机出现处解释。样本允许前指或在Results就地引入设计依据；新稿的完整协议位置按项目约定安排，并用回指连接证据，不能让读者到后文才得知改变比较含义的关键条件。

方法正文保留选择依据，标准算法的冗长推导可引用原始来源或放附录。定义关键量需要的细节留在正文；不要只报软件包名，也不要写成安装与日志说明书。

## 5. Results：由问题推进，不由文件顺序推进

**先列证据链（O6–O14）。** 对每个候选小节填写“问题—比较—图/数据—主要观察—可支持的认识”。只保留当前任务能支撑的链。下列是可选问题库，不是新增实验指令：

| 问题 | 有用证据 | 段末如何接到下一步 |
|---|---|---|
| 计算或测量是否支撑后续分析？ | 网格/时间/域或仪器验证，适当外部基准 | 确定后文可使用的设置与分析范围 |
| 系统中哪些变化与控制目标相关？ | 基准动力学、空间/时间结构、适用的稳定性等分析 | 指出需要控制或观测的对象 |
| 控制产生了什么效果？ | 评价时序、主指标、必要场图、独立于训练的评估说明 | 从效果中识别尚需解释的现象 |
| 控制改变了什么状态？ | 参考状态对照、定义明确的偏离量、相应物理证据 | 给出受控状态的解释及其边界 |
| 动作为何在此时/此处起作用？ | 事件对齐、干预或适当对照 | 从关联推进到受测试条件约束的解释 |
| 某项设计为什么有效？ | 固定其他关键条件的传感、奖励或执行器比较 | 形成有条件的设计认识 |
| 替代模型能否支撑所学控制？ | 模型预测检查与返回目标系统的闭环测试分别给出 | 将“模型近似可用”推进到“所学策略在目标系统有效” |
| 训练/计算改动带来了什么代价与收益？ | 同一任务与明确计时边界下的成本；必要时区分数据采集、建模和适配 | 与控制性能一起形成有范围的效率结论 |
| 控制需求是否取决于优化路径？ | 能辨别路径、观测或目标信息作用的可比结果；区分训练与部署信息 | 从组合可行性、路径依赖到具体归因，按证据深度选择结论 |
| 优势可以延伸到哪里？ | 明确的变化工况、扰动或外部方法对照 | 说明哪些维度、时间窗和范围受检验 |

控制过程可分启动、过渡、维持、扰动恢复，但只在数据包含这些阶段时使用。不将训练峰值、阶段切换和测试振荡混作同一现象。

**典型小节（O8、O10）：** 承接上一节留下的问题；说明本节怎样区分可能解释；介绍图中足以回答问题的比较；先报告关键趋势，再解释；以一个有条件的判断结束。解释放在 Results 还是 Discussion，遵守当前项目约定。

**设计比较（O12、O13）：** 根据科学问题组织最终方法与消融，而非“我们第一次做错，第二次终于改好”的流水账。对改变结论的反例或不一致工况如实处理，不能用删去不利条件来制造普遍优势。

## 6. 图表与正文如何分工

以样本 Figs 11–21 的功能关系为参考，不复制图面格式：

- 训练曲线说明学习过程，测试时序说明策略表现，场图说明空间状态；三者回答不同问题。
- 动作、响应和诊断曲线用相同事件/时间基准相互定位，便于比较变化的先后。
- 区域或探针图交代设计差别，指标图检验这些差别是否伴随控制效果变化。
- 方法结构图说明哪些环节不同，预测误差图说明模型能力，原系统控制曲线说明最终效果，计时图说明明确环节的成本；四者不能相互代替。
- 多面板正文先说要比较什么，再按论证顺序指出面板中的关键观察；不逐线描述全部画面。

图注通常包括对象与条件、各面板含义、曲线/符号/阴影含义及必要的处理说明。只有看过实际图或明确的图面规格才写相应细节；不能从样本借来颜色、灰区、时间点或面板字母。正文承担科学论证，图注保证独立可读；不要将整段 Discussion 塞进图注。

## 7. Discussion / Conclusions / Appendix

**Discussion：** 把直接发现、由比较支持的解释和未检验机制分开。用已核验文献说明与既有认识的联系；不把 Discussion 当成补写未做结果的地方。

**Conclusions（O15）：** 回到开篇问题，按本文实际贡献组织“获得了什么系统认识—这种认识如何用于或解释控制—证据在哪些条件下成立”。方法贡献为主时，可回收“解决的瓶颈—控制效果与实际代价—由比较得到的认识与适用条件”，不强迫添加物理设计环节。性能和效率分别对应已完成证据。不逐图重放 Results，不突然新增数值、机理或应用承诺。若用户要求简短结论，可压成一段；若物理认识与控制设计均有独立结果，可分两组。

**Appendix：** 放会打断主论证但复现需要的推导、协议和补充工况；正文给出清楚指针。不能将维系核心主张的唯一证据藏到附录并在正文省略。
